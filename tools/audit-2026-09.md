# Verification audit — September 2026

The ledger for a full verification pass over BeamerPoint: every element, every feature,
every control. Findings are recorded here as they are found, **catalogued before any is
fixed**, then fixed in severity order, each with the test that would have caught it.

A finding is marked Fixed, never deleted, so the file stays a record of what was wrong.

## Severity

| | Meaning |
| --- | --- |
| **S1** | Breaks the PDF — no output at all |
| **S2** | Silent data loss or structural loss — the model or the file quietly stops saying what the user made |
| **S3** | Wrong on the canvas — the editor disagrees with the PDF |
| **S4** | Inert control — something that moves and changes nothing |
| **S5** | Cosmetic, misleading text, or dead code |

## Why this audit exists

Before a line of it was written, the suite's central assertion was shown not to be able to
fail the way it is supposed to. The round trip — emit, parse, emit — is what makes the
LaTeX source a first-class editable view, and it was checked with byte fixpoint plus
`guard.ok`. Both hold for a deck the parser understood **none** of, because a `raw` element
re-emits its captured bytes verbatim. `health.demoted` does not close the gap either: it
counts only what the guard demoted, and a recognizer that declines produces raw the guard
never sees (`parse/guard.ts` returns early for anything already raw).

The fix is `packages/core/test/helpers/roundTrip.ts`, which adds the whole-document
fixpoint (the only signal covering the preamble) and a **census** of what the deck is made
of. F-007 below is what it found on its first run.
